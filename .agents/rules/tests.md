# 测试

适用：写或改测试、以及做代码验收时读。

## 规则

1. 默认只写端到端测试：从用户可见的入口驱动，断言外部行为（输入到输出、退出码、HTTP 响应、落库结果），不碰内部结构。
2. 集成测试与单元测试默认不写。只有下面四类才写，且每条都要能一句话说明「端到端覆盖不到」：
   - 纯算法边界：端到端构造不出那个输入
   - 配置校验与 fail-fast：启动期就退出，端到端跑不到
   - 故障注入：外部依赖不可用、超时、部分失败
   - 并发时序：需要竞态检测与屏障才能稳定复现
3. **不假定端到端设施存在**。先确认该仓库有没有可用的：有配置且能跑通 spec 才算。没有时不在功能票里新建一套——那是独立任务，先问用户要不要单独开票。验收退化为可执行冒烟：构建、类型检查、按步骤跑一遍关键路径，把命令和输出写进证据。
4. 同一行为只在一个层级断言。写之前先找已有覆盖（同包测试、集成目录、`e2e/`），能复用就复用，不再新增一份重复断言。
5. 删旧不增新：给某行为补了端到端测试后，删掉覆盖同一行为的低层测试，不留两份。
6. 不写为覆盖率而存在的测试；不 mock 到只剩自己在测自己；不为不可达分支造测试。
7. 用 `tdd` 时层级按本规则选：先写失败的端到端测试再让它变绿，不是先写单元测试。
8. 测试也是代码：命名、注释、夹具遵守 `comments.md` 与所在语言的规则；为让端到端可确定性复现而需要的极小夹具函数不算重复测试，保留。

## 检查

```bash
# 本次新增的测试文件
BASE=${BASE:-origin/main}
git diff --name-only "$BASE"...HEAD \
  | grep -Ei '(^|/)(test|tests|spec|e2e|__tests__)/|(_test\.|\.test\.|\.spec\.)' \
  || echo '(无新增测试)'
```

判定：新增测试要么是端到端，要么对得上规则 2 的四类之一；同一行为出现两份断言即 FAIL。仓库无可用端到端设施时，按规则 3 检查冒烟证据是否齐全。
