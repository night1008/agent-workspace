# 测试规范

适用：编写、修改测试或执行代码验收时读。

## 规则

1. **端到端优先**：默认仅编写端到端测试，从入口断言外部可观察行为（输入输出、退出码、HTTP 响应、数据库状态），不测内部结构。
2. **低层测试例外**：单元与集成测试默认不写；仅允许覆盖端到端无法触及的四类场景：
   - 纯算法边界分支；
   - 进程启动期配置校验与 fail-fast；
   - 外部依赖故障与超时注入；
   - 依赖特定时序与竞态检测的并发状态。
3. **设施现状依赖**：禁止在业务任务中从零搭建端到端测试框架。无可用端到端设施时，验收退化为冒烟命令验证（构建 + 类型检查 + 关键路径执行），并记录输出证据。
4. **单层断言**：同一业务行为只允许在一个层级断言，禁止重复覆盖。新增高层测试后，删除覆盖相同行为的旧低层测试。
5. **禁止无价值测试**：禁止追求盲目覆盖率、禁止过度 mock 导致仅验证 mock 自身行为、禁止为理论不可达分支编写测试。
6. **TDD 节奏**：使用 `tdd` 时，优先编写失败的端到端用例，再实现并转绿。

## 检查

```bash
BASE=${BASE:-origin/main}

# 检查新增的测试文件
git diff --name-only "$BASE"...HEAD \
  | grep -Ei '(^|/)(test|tests|spec|e2e|__tests__)/|(_test\.|\.test\.|\.spec\.)' \
  || echo '(无新增测试)'
```

判定：新增测试必须为端到端测试，或符合规则 2 的四类例外之一；同一行为存在两份断言直接判 FAIL。
