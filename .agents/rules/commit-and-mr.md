# 提交与 MR 规范

适用：在 `repos/<repo>/` 里写 commit message、开 MR/PR 之前。

## 规则

1. **任务号从分支名取**，不要自己编排。`repos/<repo>/` 的工作分支是 `t<编号>-<slug>` 形态（如 `t217244-skill-security`），开头的飞书任务号就是唯一来源：

   ```bash
   git rev-parse --abbrev-ref HEAD | grep -Eo '^t[0-9]+'
   ```

2. **标题**：`<type>(<scope>): <中文描述> t<编号>`，形如 `fix(web): 修复分布分析零值分桶重复导致的面板查询越界 t217244`。类型前缀保留英文、描述用中文，沿用 `AGENTS.md` 的既有约定。标题说清现象，不写 `-0`、`+∞` 这类符号（会被读成减号或运算符）。
3. **正文必填**：只写标题的提交一律补正文。正文用中文 bullet points，回答三件事：为什么改（触发问题的现象或需求背景）、改了什么（按影响面写，不逐文件复述 diff）、怎么验证（实际跑过的命令或场景）。typo、单行修复、纯文案这类一两行能说清的小改动可以只有标题。
4. **正文不写**：任务号（标题已带）、文件清单、`修改了 xxx` 这类流水账、代码里已经能看出来的实现细节。
5. **MR 标题也以任务号结尾**，形如 `fix(web): 修复分布分析零值分桶重复导致的面板查询越界 t217244`；描述正文不再重复写任务号。
6. **MR 描述**按四块写：背景、改动点、验证方式、风险；截图或复现步骤放这里，不放进 commit 正文。
7. 一个分支的多条 commit 用同一个尾部任务号，不混入第二个号。
8. 分支上没有任务号（`master`、`backup/*`、`mr-*` 这类）时先问用户要任务号，不要用其它编号替代，也不要省略。

## 检查

```bash
branch=$(git rev-parse --abbrev-ref HEAD)
echo "$branch" | grep -Eq '^t[0-9]+' || echo "分支名未以任务号开头"
git log -1 --pretty=%s | grep -Eq 't[0-9]+$' || echo "最近一条 commit 未以任务号结尾"
git log -1 --pretty=%b | grep -q '[^[:space:]]' || echo "最近一条 commit 没有正文"
```
