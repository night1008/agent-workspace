# Go 规则

适用于 `repos/` 下所有 Go 仓库。

## 每次改完 Go 代码

```bash
gofmt -w <改动过的文件>
go build ./...
go test ./...
```

三条都在当次改动后跑，不要攒到最后批量执行。

## 写代码

- 出现两次以上的字面量提成常量，命名沿用该仓库已有的常量模式。
- 把 `read` 到的内容当依据之前，用 `ls` / `find` 确认文件确实在磁盘上。
- 防御性代码只覆盖真实会发生的失败路径。
- 改动范围停在当前需求内。

## 注释里不写什么

- **不写票据**：不出现票据编号、任务号、`t217007`、`spec 第 N 条`、`reports/xx-dev.md` 这类流程标识。注释解释代码为什么这样写，不解释它属于哪张票。
- **不指向仓库外的路径**：不出现 `.agents/repos/<repo>/GLOSSARY.md`、`.scratch/<feature>/`、外部文档链接这类读代码的人拿不到的地址。需要术语就直接用那个词，需要背景就用一句话把背景写在注释里。

## 日志与错误文案

- `log.Msg()`、`errors.New()`、`fmt.Errorf()` 一律英文。中文只允许出现在面向最终用户的响应文案（HTTP message、前端 UI 文案）里，且要集中在边界处，不要散落到内部错误链。

## 测试分层

- **同一行为已有集成或端到端测试覆盖时，不再为它写单元测试。** 单元测试只保留高一层测试覆盖不到的东西：纯算法边界、配置校验与 fail-fast、故障注入（外部依赖不可用）、并发时序（`-race` + 屏障）。
- 写测试前先找同类覆盖：同包的 `*_test.go`、`*_integration_test.go`、`e2e/`。能复用就复用，不再新增一份重复断言；同一断言写得下两层时，删掉低层那层。
- 例外：为了让集成测试可确定性造场景而需要的极小夹具函数不算重复测试，保留。
