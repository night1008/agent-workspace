# 注释规范

适用：编写、修改任何语言的代码或执行代码验收时读。

## 核心原则：尽量少写，甚至不写

以**零注释（Zero Comments）**为默认追求。优秀的代码依靠清晰的命名、精炼的函数划分与自解释的结构表达逻辑。写注释应被视为代码表达力受限时的最后手段：**能不写就坚决不写**。

## 规则

1. **能不写绝不写**：默认零注释。凡是可通过改善变量/函数命名、拆解小函数、消除魔法值等方式自解释的代码，一律不写注释。
2. **只写「为什么」**：仅记录非直观的架构取舍、特殊的第三方缺陷绕行（Workaround）或系统反常行为。严禁复述代码行为（「是什么」）、罗列执行步骤（「怎么做」）或记录流程信息（任务号、票据号、spec 编号）。
3. **单句检验**：单条注释严格限制为极简的一句话，且必须能够明确回答「不写此句会导致何种隐蔽误解或暗坑」，否则一律删除。
4. **语言约束**：极少数确需保留的新增注释严格使用英文。仅在引用专有中文业务术语或合规条款时允许双引号包裹中文原词。原有未改动注释不无故批量修改。
5. **结构禁止**：严禁段落式长注释、占位性文档注释与装饰性分块标题（如 `# ---- 数据处理 ----`），依靠空行与函数边界自然分节。
6. **清理废弃代码**：严禁保留被注释掉的代码，直接物理删除。
7. **禁止外部路径**：严禁在注释中引用工作区外部路径（如 `.agents/...`、`.scratch/...`）或不可达链接。

## 检查

```bash
BASE=${BASE:-origin/main}

# 提取当前 diff 新增的注释与中文统计
git diff "$BASE"...HEAD -U0 -- '*.go' '*.sh' '*.ts' '*.js' '*.py' \
  | grep -E '^\+[[:space:]]*(#|//|/\*|\*)' > /tmp/new-comments.txt || true

wc -l < /tmp/new-comments.txt
grep -c '[一-龥]' /tmp/new-comments.txt || true
```

判定：新增注释行数为 0 为最佳实践，直接通过；若大于 0，逐行严审必要性（凡可不写的即删）并核对规则 2 与规则 4，任一行违背即判 FAIL。
