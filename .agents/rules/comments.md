# 注释

适用：写或改任何语言的代码、以及做代码验收时读。

## 规则

1. 默认不写注释。代码能表达的不写；优先用改名、提取函数、拆小函数来消除「需要解释」这件事。
2. 只允许写「为什么」：非直观的取舍、规避已知缺陷的原因、外部系统的反常行为。不允许写「是什么」（复述代码）、「怎么做」（拆解步骤）、「属于哪张票」：票据编号、任务号、`spec 第 N 条`、报告文件名这类流程标识一律不进注释，注释解释代码为什么这样写，不解释它属于哪张票。
3. 一条注释一句话，必须能回答「不写这句，读代码的人会怎样误解」。答不上来就删掉。
4. 语言默认英文。中文只在两种情况下出现：引用的中文业务术语、中文合规条款或中文文档标题，且必须加引号括住原文；同一句里其余部分仍是英文。英文优先只针对新增代码：原有注释不必为了这条规则改成英文，除非你正在改动那段代码且中文注释已经影响理解。
5. 不写段落式注释和分节标题注释（`# ---- 数据处理 ----` 这类）。分节靠空行与函数边界。
6. 被注释掉的代码一律删除，不留「以后可能要用」。
7. 不指向仓库外的路径：不写 `.agents/repos/<repo>/GLOSSARY.md`、`.scratch/<feature>/`、外部文档链接这类读代码的人拿不到的地址。需要术语就直接用那个词；需要背景就用一句话把背景写进注释。

## 检查

```bash
# 本次 diff 新增的注释行数，以及其中含中文的行数
BASE=${BASE:-origin/main}
git diff "$BASE"...HEAD -U0 -- '*.go' '*.sh' '*.ts' '*.js' '*.py' \
  | grep -E '^\+[[:space:]]*(#|//|/\*|\*)' > /tmp/new-comments.txt || true
wc -l < /tmp/new-comments.txt
grep -c '[一-龥]' /tmp/new-comments.txt || true
```

判定：新增注释为 0 直接通过；否则逐行核对规则 2 与规则 4，任一行不满足即 FAIL。
