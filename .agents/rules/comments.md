# 注释规范

适用：编写、修改任何语言的代码或执行代码验收时读。

## 规则

1. **默认不写**：代码已表达的逻辑一律不写。优先通过重命名与函数拆解消除解释需求。
2. **只写「为什么」**：仅记录非直观取舍、缺陷规避原因与外部系统反常行为。严禁复述代码行为（「是什么」）、罗列步骤（「怎么做」）或记录流程编号（任务号、票据号、spec 序号）。
3. **单句检验**：单条注释限一句话，且必须说明「不写会导致何种误解」，否则删除。
4. **语言约束**：新增注释默认英文。仅在引用专有中文业务术语或合规条款时允许双引号包裹中文原词。原有未改动注释不无故批量修改。
5. **结构禁止**：严禁段落式注释与装饰性分块标题（如 `# ---- 数据处理 ----`），依靠空行与函数边界分节。
6. **清理废弃代码**：严禁保留被注释掉的代码，直接物理删除。
7. **禁止外部路径**：严禁在注释中引用工作区外部路径（如 `.agents/...`、`.scratch/...`）或不可达链接。

## 检查

```bash
BASE=${BASE:-origin/main}

# 提取当前 diff 新增的注释与中文统计
git diff "$BASE"...HEAD -U0 -- '*.go' '*.sh' '*.ts' '*.js' '*.py' \
  | grep -E '^\+[[:space:]]*(#|//|/\*|\*)' > /tmp/new-comments.txt || true

wc -l < /tmp/new-comments.txt
grep -c '[一-龥]' /tmp/new-comments.txt || true
```

判定：新增注释行数为 0 直接通过；若大于 0，逐行核对规则 2 与规则 4，任一行违背即判 FAIL。
