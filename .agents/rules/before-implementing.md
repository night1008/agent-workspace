# 动手之前：对齐协议

适用：新模块、新接口、schema 变更、数据迁移、鉴权、计费、破坏性删除等非平凡改动。微小改动（改名、typo、20 行内确定性小改）直接做，不走这套。

## 1. 独立自查

代码、测试、配置与依赖清单自行查阅。已有规范、现有抽象、测试框架、语言版本严禁提问；仅在发现代码库存在自相矛盾时提出。

## 2. 产出四块并中断等待

严格产出以下四项，产出后立即停下等待确认，禁止自行开始实现：

1. **目标**：一段话复述需求目标与验收标准。
2. **阻塞问题（0–3 个）**：仅在答错会导致整块返工时提出，每个问题必须附带推荐默认值；无阻塞问题显式写 0 个。
3. **假设**：编号、具体、可证伪（数据边界、失败路径、并发时序、明确不做的范围、测试边界）。
4. **方案**：改动文件列表、关键函数与类型签名、执行顺序；若有设计取舍，一句话说明被否决的备选方案。

## 3. 方案落地与收尾

- 获得确认后方可编码。执行中若发现既定假设失效，停下重新说明，禁止隐蔽变更设计。
- 完成后执行消融检验：确认每一处新增逻辑与测试都真实起效。
